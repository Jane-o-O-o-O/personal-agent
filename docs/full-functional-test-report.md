## 修复与复验

本轮发现并修复了原生表单提交后的 URL/title 元数据不及时和画面停止更新的问题。修复包括目标信息回查、主框架事件刷新、并发刷新版本校验，以及原生流静默时的截图回退。

复核还发现跨标签及跨文档共用未完成截图的风险。截图现在按 target、控制版本、Chrome loaderId 区分；旧文档结果被拒绝，旧标签结果不会标成新标签画面，旧 Promise 完成不会清空新捕获引用。切换原生流不等待截图完成；前端不再在 HTTP 返回后无条件清空已到达的新帧。

本地针对性测试覆盖人工延迟真实旧截图、延迟 HTTP 回包，以及原生流停止后目的页面绿/红/蓝像素的持续更新检查。

公网切标签的积压已定位：服务器约 150–300ms 生成并发出新帧，客户端却继续接收旧标签帧，新画面曾约 7–8 秒后才到达。WebSocket `bufferedAmount=0` 无法排除 TCP/代理层积压。工作台现在通过 `?ack=1` 逐帧确认，服务端只留一张在途帧和一张最新待发帧，精确 sequence 确认后发送最新画面，15 秒无确认关闭连接；旧客户端协议保留。共享截图 Promise 的同一结果不会重复广播。

完整前序操作下的切第二标签样本由 7720ms 降至 491ms，切回样本为 993ms；这些是单次观测，不是性能保证。最终部署关闭诊断日志后，VPS 17 项浏览器流程再次全部通过，桌面及 360px 截图已目视核验。

真实模型还揭示两处工具契约问题：浏览器说明误列不存在的 `text(value)`/`image(bytes)`，已改成 worker 实际支持的 `console.log`、最终表达式和截图接口；MCP 扩展原默认读取宿主全局 Pi 目录，现通过公开 `loadConfig` 选项明确读取本项目 `dataDir/pi/mcp.json`，日志也限定同目录。真实 SDK 回归确认外部宿主配置没有被连接或改写。

另一次正向 MCP 测试中，模型只在聊天中询问批准，没有创建应用内批准请求。系统约定已明确：调用受保护工具来创建审批，由服务端阻止执行直到精确参数被批准；聊天文字不能代替批准记录。原测试提示和业务断言保留，完整阶段重新执行后通过；批准前上游调用为 0，批准后为 1，拒绝仍为 0。
