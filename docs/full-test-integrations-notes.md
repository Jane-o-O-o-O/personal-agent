# 本轮生活数据与消息渠道验收

本轮日期：2026-10-03。目标：配合最新已保存模型凭据的全量验收，核对 VPS 当前真实可用的连接器。本文仅覆盖生活数据、MCP 和微信的连接状态；模型任务、浏览器、批准与重启恢复由整体验收报告记录。

## 验收范围

脚本 `scripts/verify-live-integrations.mjs` 使用统一临时登录客户端，调用 `/api/integrations`、已实现连接器的 `/test` 和微信登录状态接口。脚本不修改凭据，不创建任务，不操作浏览器，不发送消息，不创建订单。连接测试按产品实现会更新 `lastCheckedAt`、`verified` 和 `lastError`，但不改变用户配置。

每项结果区分真实连接通过、缺少凭据而跳过、停用而跳过、仅观察状态和失败。未配置服务只读取状态，不发起其连接测试；微信未配置状态核对不等于该平台真实联通。结果保存在 `.runtime/full-verification/integrations.json`，不记录密钥或完整配置。

## 资源库与产品能力的边界

`resources/ecosystem` 有 78 项开发资产，包括源码、Skill、CLI、MCP 发布包、数据与 API 文档。这些文件用于后续实现和核对，数量不等于应用已启用工具数量。当前 Pi 运行时显式使用 `noSkills: true`，不会自动执行资源库内的 Skills。

普通外卖、瑞幸自提、滴滴叫车、机票/火车票查询与购买、快递、飞书/腾讯文档写入等尚未接成当前应用工具。本轮不能将它们写成已实测成功。瑞幸、滴滴与票务等各平台的账号、沙箱或生产权限仍需独立接入；需要付费或产生订单的动作还要核对确切回执。

## MCP 真实 HTTP 场景

使用受控 Streamable HTTP fixture，可验证 `initialize`、`notifications/initialized`、`tools/list` 与 `tools/call`，返回带唯一测试标签的查询结果。服务端记录真实调用次数：用户批准前为 0，批准后为 1；新的请求被拒绝后计数保持 1。该场景说明 MCP 协议、Pi 工具发现与批准链路正常，不说明某一厂商 MCP 已授权或可用。根验收负责该场景并恢复原 MCP 配置。
